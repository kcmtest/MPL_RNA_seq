Module 1 — RNA-seq Fundamentals

What does RNA-seq measure?

Biological signal

RNA-seq samples RNA molecules present in a biological specimen and converts them into sequenceable libraries.

RNA abundance → fragments → reads → mapped fragments → gene/transcript abundance

Important limitation

RNA-seq does not directly count intact RNA molecules.

Observed counts can be influenced by library preparation, GC content, sequencing depth, RNA quality and mapping ambiguity.

What can bulk RNA-seq tell us?

Expression

Which genes are expressed?

Sample relationships

Do replicates cluster together?

Differential expression

Which genes change between conditions?

Quality control

Are there outliers or batch effects?

Pathways

Which biological programs are enriched?

Phenotype

Which gene programs characterize the phenotype?

Bulk RNA-seq vs single-cell RNA-seq

Feature Bulk RNA-seq scRNA-seq
Unit measured Sample / tissue Individual cell / nucleus
Main output Average expression Cell-level expression matrix
Depth per unit High Lower per cell
Typical question Condition-level DE Cell types, states, trajectories
Complexity Moderate High
Composition effects Can confound DE Can be modeled explicitly

Common RNA-seq library strategies

Poly(A) selection

Enriches polyadenylated RNA and is commonly used for mRNA profiling.

rRNA depletion

Removes ribosomal RNA while retaining a broader range of RNA species.

Stranded libraries

Preserve transcript-strand information and improve assignment in overlapping loci.

Paired-end sequencing

Improves mapping across splice junctions and transcript structures.

Module 2 — Experimental Design

The most important analysis step happens before sequencing

A sophisticated statistical model cannot rescue a fundamentally confounded experiment.

  • What is the biological unit of replication?
  • What is the primary comparison?
  • Are replicates independent?
  • Are important covariates recorded?
  • Is batch balanced across conditions?
  • Is the design paired, longitudinal or factorial?

Biological vs technical replicates

Biological replicates

Independent biological samples that capture biological variability and support inference beyond the samples measured.

Technical replicates

Repeated measurement of the same biological material and mainly characterize technical variability.

Three sequencing lanes from the same RNA extraction are not three biological replicates.

Confounding example

Sample Condition Batch
S1 Control Batch1
S2 Control Batch1
S3 Treated Batch2
S4 Treated Batch2

Problem

Condition and batch are perfectly confounded. The model cannot determine whether the difference is caused by condition or batch.

Choosing a DESeq2 design formula

# Simple two-group design
design = ~ condition

# Adjust for batch
design = ~ batch + condition

# Paired design
design = ~ patient + condition

# Interaction design
design = ~ genotype + treatment + genotype:treatment

Module 3 — FASTQ to Count Matrix

FASTQ anatomy

@READ_ID
ACGTTGCA...
+
FFFFFFFF...

The quality line encodes per-base Phred quality scores.

\[ Q = -10\log_{10}(P_{error}) \]

Q30 corresponds to an estimated base-call error probability of 0.001.

Raw-read QC

  • Per-base sequence quality
  • Sequence quality distribution
  • Adapter content
  • Overrepresented sequences
  • GC distribution
  • Sequence duplication
  • Read-length distribution
  • Ambiguous bases

A FastQC warning is a diagnostic signal, not automatically a reason to discard a sample.

Example QC commands

mkdir -p fastqc_raw
fastqc *.fastq.gz -o fastqc_raw -t 8
multiqc fastqc_raw -o multiqc_raw

Alignment-based workflow

STAR: conceptual example

STAR \
  --genomeDir star_index \
  --readFilesIn sample_R1.fastq.gz sample_R2.fastq.gz \
  --readFilesCommand zcat \
  --runThreadN 16 \
  --outSAMtype BAM SortedByCoordinate \
  --outFileNamePrefix sample.

Gene counting with featureCounts

featureCounts \
  -T 8 \
  -p \
  -s 0 \
  -a annotation.gtf \
  -o gene_counts.txt \
  *.bam

Important parameters: paired-end status, strandedness, annotation version and fragment/read counting behavior.

  • Exonic / intronic / intergenic distribution

Module 5 — DESeq2 Fundamentals

Why not compare raw counts directly?

DESeq2 models counts using a negative binomial framework.

DESeq2 model

\[ K_{ij} \sim NB(\mu_{ij}, \alpha_i) \]

  • \(K_{ij}\) = observed count for gene \(i\) in sample \(j\)
  • \(\mu_{ij}\) = expected count
  • \(\alpha_i\) = gene-specific dispersion

DESeq2 workflow

Create the DESeq2 object

metadata$condition <- relevel(
  factor(metadata$condition),
  ref = "Control"
)

dds <- DESeqDataSetFromMatrix(
  countData = round(counts_filtered),
  colData = metadata,
  design = ~ condition
)

Run the model and obtain a contrast

dds <- DESeq(dds)

res <- results(
  dds,
  contrast = c("condition", "Treated", "Control"),
  alpha = 0.05
)

Interpreting log2 fold change

Positive log2FC

Higher expression in Treated relative to Control.

Negative log2FC

Lower expression in Treated relative to Control.

Multiple-testing correction

A common workshop threshold:

padj < 0.05
AND
|log2FoldChange| >= 1

This is a reporting threshold, not a universal biological law.

Variance-stabilizing transformation

vsd <- vst(dds, blind = FALSE)

PCA

Module 7 — Differential Expression Results

MA plot

plotMA(res, alpha = 0.05, ylim = c(-5, 5))

The MA plot compares effect size against mean abundance.

Create a DE results table

res_df <- as.data.frame(res) |>
  rownames_to_column("gene_id") |>
  mutate(
    status = case_when(
      !is.na(padj) & padj < 0.05 & log2FoldChange >= 1 ~ "Up",
      !is.na(padj) & padj < 0.05 & log2FoldChange <= -1 ~ "Down",
      TRUE ~ "Not significant"
    )
  )

Volcano plot

EnhancedVolcano(
  res_df,
  lab = res_df$gene_id,
  x = "log2FoldChange",
  y = "padj",
  pCutoff = 0.05,
  FCcutoff = 1,
  title = "Treated vs Control"
)

Heatmap of top DE genes

top_de <- res_df |>
  filter(status != "Not significant") |>
  arrange(padj) |>
  slice_head(n = 30)

mat <- assay(vsd)[top_de$gene_id, , drop = FALSE]
mat_z <- t(scale(t(mat)))

pheatmap(mat_z)

Module 9 — Functional Enrichment Concepts

From genes to biology

ORA vs GSEA

ORA

Input: selected significant gene list

Question: Are some gene sets represented more than expected?

Examples: GO and KEGG enrichment

GSEA

Input: ranked list of many / all tested genes

Question: Do pathway genes accumulate toward one end of the ranking?

Advantage: detects coordinated modest shifts

Gene Ontology

BP — Biological Process

What biological program is occurring?

MF — Molecular Function

What molecular activity is performed?

CC — Cellular Component

Where is the gene product acting?

ORA background matters

The ORA background / universe should represent genes that had a reasonable opportunity to be selected — not automatically every annotated gene in the genome.

Module 10 — GO Enrichment

Prepare significant genes

sig_entrez <- res_annotated |>
  filter(
    !is.na(ENTREZID),
    !is.na(padj),
    padj < 0.05,
    abs(log2FoldChange) >= 1
  ) |>
  pull(ENTREZID) |>
  unique()

background_entrez <- res_annotated |>
  filter(!is.na(ENTREZID)) |>
  pull(ENTREZID) |>
  unique()

Run GO Biological Process enrichment

ego_bp <- enrichGO(
  gene = sig_entrez,
  universe = background_entrez,
  OrgDb = org.Hs.eg.db,
  keyType = "ENTREZID",
  ont = "BP",
  pAdjustMethod = "BH",
  readable = TRUE
)

GO visualization

dotplot(ego_bp, showCategory = 20) +
  ggtitle("GO Biological Process enrichment")

Module 13 — GSEA

Why GSEA?

ORA

Requires a threshold that divides genes into selected and not selected.

GSEA

Uses a ranked list and asks whether genes from a pathway accumulate toward the top or bottom.

Create a ranked gene list

rank_df <- res_annotated |>
  filter(!is.na(ENTREZID), !is.na(stat)) |>
  distinct(ENTREZID, .keep_all = TRUE)

gene_list <- rank_df$stat
names(gene_list) <- rank_df$ENTREZID
gene_list <- sort(gene_list, decreasing = TRUE)

GO GSEA

gsea_go <- gseGO(
  geneList = gene_list,
  OrgDb = org.Hs.eg.db,
  keyType = "ENTREZID",
  ont = "BP",
  pAdjustMethod = "BH",
  verbose = FALSE
)

Understanding NES

Positive NES

Gene set enriched toward the positive / top end of the ranking.

Negative NES

Gene set enriched toward the negative / bottom end of the ranking.

Module 14 — Interpretation Framework

A defensible interpretation sequence

Avoid common interpretation errors

  • Using p < 0.05 without multiple-testing correction.
  • Treating tiny significant fold changes as automatically important.
  • Using TPM / FPKM directly as DESeq2 input.
  • Ignoring PCA outliers.
  • Ignoring batch or paired structure.
  • Treating every GO term as an independent discovery.
  • Using an inappropriate ORA background.
  • Ignoring failed or duplicated ID mappings.

Module 15 — Troubleshooting

Low mapping rate

Possible causes

Wrong reference • contamination • poor read quality • adapters • short inserts • rRNA abundance • species mismatch • library issue

PCA outlier

Check

Sample identity • library size • mapping rate • RNA quality • batch • contamination • biological heterogeneity • metadata accuracy

Do not remove an outlier simply because it makes the desired comparison look cleaner.

Too many or no DE genes

Too many DE genes

Strong biology • batch confounding • composition shift • wrong contrast • underestimated variability

No significant DE genes

Weak effect • low power • high variability • wrong contrast • technical noise • poor design

Final Take-home Messages

Five principles to remember

1. Experimental design determines what can be inferred.

2. QC is continuous — from FASTQ through biological interpretation.

3. Use raw counts for count-based differential-expression models.

4. Effect size, uncertainty and sample-level patterns must be interpreted together.

5. Enrichment summarizes gene-level results; it does not prove pathway activation.
