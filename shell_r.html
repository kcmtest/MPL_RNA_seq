Session 1 — Shell Fundamentals

Why use the command line in bioinformatics?

The shell is useful because sequencing analysis is often:

  • file-oriented;
  • repetitive;
  • performed on Linux servers;
  • dependent on command-line tools;
  • easier to automate than manual clicking.

The shell is the practical bridge between raw sequencing files and the count matrix that will later enter R.

Terminal vs shell

Terminal

The window or application where commands are entered.

Examples:

  • Windows Terminal
  • Git Bash
  • VS Code terminal
  • Linux terminal

Shell

The program that interprets those commands.

Examples:

  • Bash
  • Zsh
  • PowerShell

pwd
ls -lh

Move between directories:

cd RNAseq

Practice

Navigate into the workshop folder and confirm the current directory with pwd.

Absolute vs relative paths

Absolute path

/home/user/RNAseq/fastq/sample_R1.fastq.gz

Starts from the filesystem root.

Relative path

fastq/sample_R1.fastq.gz

Starts from the current working directory.

Relative paths make projects easier to move between systems.

Organize an RNA-seq project

RNAseq/
├── fastq/
├── qc/
├── alignment/
├── counts/
├── scripts/
└── results/

Create directories:

mkdir -p qc alignment counts scripts results

Good organization reduces accidental overwriting and makes troubleshooting easier.

Inspect files without opening huge datasets

Small text files:

head metadata.csv
tail metadata.csv

Compressed FASTQ:

zcat sample_R1.fastq.gz | head

Count lines:

wc -l metadata.csv

Pipes: connect commands together

zcat sample_R1.fastq.gz | head

The pipe | sends the output of one command directly into another command.

Redirect output and logs

Save output:

command > output.txt

Append:

command >> output.txt

Save errors:

command 2> error.log

Save both output and errors:

command > run.log 2>&1

Logs are essential for reproducibility and troubleshooting.

Search text with grep

grep "PASS" results.txt

Case-insensitive:

grep -i "error" pipeline.log

Multiple patterns:

grep -E "error|warning|failed" pipeline.log

Useful in bioinformatics logs, VCFs and QC summaries.

Wildcards

ls *.fastq.gz

can match:

Control1_R1.fastq.gz
Control1_R2.fastq.gz
Treated1_R1.fastq.gz
Treated1_R2.fastq.gz

Wildcards are powerful. Always check which files match before using them with destructive commands.

Shell variables

sample="Control01"

R1="${sample}_R1.fastq.gz"
R2="${sample}_R2.fastq.gz"

echo "$R1"

Why variables?

  • reduce repeated typing;
  • make scripts reusable;
  • reduce filename mistakes.

Loops: repeat the same task

for file in *.fastq.gz
do
  echo "$file"
done

RNA-seq example:

for file in *.fastq.gz
do
  fastqc "$file" -o qc/
done

A minimal shell script

#!/usr/bin/env bash
set -euo pipefail

mkdir -p qc

fastqc *.fastq.gz -o qc/
multiqc qc/ -o qc/

Run:

chmod +x run_qc.sh
./run_qc.sh

tidyverse: the core data-manipulation verbs

Function Purpose
filter() keep rows
select() keep columns
mutate() create/modify columns
arrange() sort rows
group_by() define groups
summarise() summarize groups
left_join() combine tables

Pipe operator

results |>
  filter(padj < 0.05) |>
  arrange(padj)

Read it as:

take results
      ↓
filter rows
      ↓
sort by padj

Factors matter for experimental groups

metadata$condition <- factor(
  metadata$condition
)

Set reference level:

metadata$condition <- relevel(
  metadata$condition,
  ref = "Control"
)

Factors tell R which values represent experimental categories and which level should be treated as the reference.

The most important pre-DE check

Count matrix:

colnames(counts)

Metadata:

rownames(metadata)

Check:

identical(
  colnames(counts),
  rownames(metadata)
)

Expected:

TRUE

If these are mismatched, the wrong biological labels can be assigned to the wrong expression profiles.

Reorder metadata safely

metadata <- metadata[
  colnames(counts),
  ,
  drop = FALSE
]

Then confirm:

stopifnot(
  identical(
    colnames(counts),
    rownames(metadata)
  )
)

Missing values and summaries

Missing values:

is.na(metadata)

Sample groups:

table(metadata$condition)

Dimensions:

dim(counts)

Library totals:

colSums(counts)

These are simple checks before statistical modeling.

Ready for Differential Expression

What must be ready before DESeq2 or edgeR?

Checklist:

  • raw gene counts available;
  • sample names verified;
  • metadata complete;
  • conditions encoded correctly;
  • reference group understood;
  • important covariates identified.
